# Autenticación con Cookies httpOnly y Secure

Esta guía documenta la implementación completa de autenticación usando cookies httpOnly y secure en el backend (NestJS) y frontend (Next.js), para mejorar la seguridad frente a ataques XSS y CSRF.

## ¿Por qué usar cookies httpOnly?
- **httpOnly**: No accesible por JavaScript, protege el token ante XSS.
- **secure**: Solo se envía por HTTPS en producción.
- **SameSite**: Limita el envío de la cookie a contextos de primer nivel (recomendado: `Lax` o `Strict`).

```typescript
import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { AppModule } from './app.module';
import * as cookieParser from 'cookie-parser';
import * as dotenv from 'dotenv';
import { join } from 'path';

dotenv.config();

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);
  
  // Habilitar cookie-parser para leer cookies httpOnly
  app.use(cookieParser());
  
  app.enableCors({
    origin: [
      'http://localhost:3000',
      'https://enfoqueqr.cl',
      'https://www.enfoqueqr.cl',
    ],
    credentials: true, // CRÍTICO: permite envío de cookies
  });

  app.useStaticAssets(join(process.cwd(), 'public'), {
    prefix: '/public/',
  });

  await app.listen(3001);
}
bootstrap();
```

### 2. JWT Strategy - Lectura de Cookies

**Archivo: `backend/src/auth/jwt.strategy.ts`**
```typescript
import { Injectable } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    super({
      jwtFromRequest: ExtractJwt.fromExtractors([
        (req) => req?.cookies?.token, // Extraer token desde cookie httpOnly
      ]),
      ignoreExpiration: false,
      secretOrKey: process.env.JWT_SECRET,
    });
  }

  async validate(payload: any) {
    return {
      userId: payload.sub,
      email: payload.email,
      institutionId: payload.institutionId,
      role: payload.role,
    };
  }
}
```

### 3. Auth Controller - Login y Logout

**Archivo: `backend/src/auth/auth.controller.ts`**
```typescript
import { Controller, Post, Body, Res, Get, UseGuards, Request } from '@nestjs/common';
import { Response } from 'express';
import { AuthService } from './auth.service';
import { JwtAuthGuard } from './jwt-auth.guard';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('login')
  async login(
    @Body() body: { email: string; password: string },
    @Res({ passthrough: true }) res: Response
  ) {
    const { token, user } = await this.authService.login(body.email, body.password);
    
    // Enviar token como httpOnly cookie
    res.cookie('token', token, {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'lax',
      maxAge: 24 * 60 * 60 * 1000, // 24 horas
    });
    
    return { user };
  }

  @Get('me')
  @UseGuards(JwtAuthGuard)
  async getProfile(@Request() req) {
    return req.user;
  }

  @Post('logout')
  async logout(@Res({ passthrough: true }) res: Response) {
    res.clearCookie('token');
    return { message: 'Logout successful' };
  }
}
```

## Implementación en el Frontend (Next.js)

### 1. AuthContext - Gestión de Autenticación

**Archivo: `front/contexts/AuthContext.js`**
```javascript
import React, { createContext, useContext, useState, useEffect } from 'react';
import { useRouter } from 'next/router';

const AuthContext = createContext();

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const router = useRouter();

  useEffect(() => {
    // Verificar autenticación consultando /auth/me
    const checkAuth = async () => {
      try {
        const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/auth/me`, {
          credentials: 'include',
        });
        if (res.ok) {
          const userData = await res.json();
          setUser(userData);
        } else {
          setUser(null);
        }
      } catch (error) {
        setUser(null);
      } finally {
        setLoading(false);
      }
    };
    checkAuth();
  }, []);

  const login = async (userData) => {
    // El token ya está en la cookie httpOnly
    setUser(userData);
  };

  const logout = async () => {
    try {
      await fetch(`${process.env.NEXT_PUBLIC_API_URL}/auth/logout`, {
        method: 'POST',
        credentials: 'include',
      });
    } catch (error) {
      console.error('Error al hacer logout:', error);
    }
    setUser(null);
    router.push('/');
  };

  return (
    <AuthContext.Provider value={{ user, login, logout, loading }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  return useContext(AuthContext);
}
```

## Endpoints de Autenticación

### `POST /auth/login`
**Request:**
```json
{
  "email": "usuario@ejemplo.com",
  "password": "password123"
}
```

**Response:**
```json
{
  "user": {
    "id": 1,
    "email": "usuario@ejemplo.com",
    "institutionId": 1,
    "role": "admin"
```

## Seguridad Implementada

### ✅ Protección contra XSS
- Token NO accesible por JavaScript (`httpOnly: true`)
- Imposible robar el token con scripts maliciosos

### ✅ Protección CSRF Básica
- `sameSite: 'lax'` previene envío en contextos de terceros
- En producción considerar `sameSite: 'strict'` o tokens CSRF adicionales

### ✅ HTTPS en Producción
- `secure: true` cuando `NODE_ENV === 'production'`
- Cookie solo se envía por conexiones seguras

### ✅ Expiración de Sesión
- `maxAge: 24 * 60 * 60 * 1000` (24 horas)
- Cookie se elimina automáticamente después de este tiempo

### ✅ CORS Configurado
- `credentials: true` permite cookies en requests cross-origin
- Origins específicos configurados (no wildcard)

## Recomendaciones Adicionales

### 1. Proteger Endpoints Sensibles
Agregar `@UseGuards(JwtAuthGuard)` a todos los endpoints que modifican datos:
```typescript
@Controller('equipments')
export class EquipmentController {
  @UseGuards(JwtAuthGuard)
  @Post()
  create(@Body() data: any) {
    // ...
  }
  
  @UseGuards(JwtAuthGuard)
  @Delete(':id')
  remove(@Param('id') id: string) {
    // ...
  }
}
```

### 2. Validación de Institución
En endpoints críticos, verificar que el usuario pertenece a la institución del recurso:
```typescript
@UseGuards(JwtAuthGuard)
@Get('equipments')
async findAll(@Request() req) {
  const institutionId = req.user.institutionId;
  return this.equipmentService.findByInstitution(institutionId);
}
```

### 3. Refresh Tokens (Opcional)
Para sesiones más largas, implementar refresh tokens con mayor duración:
- Access token (cookie httpOnly): 15 minutos
- Refresh token (cookie httpOnly): 7 días
- Endpoint `/auth/refresh` para renovar access token

### 4. Logging de Seguridad
Registrar intentos de login fallidos y accesos sospechosos.

## Troubleshooting

### Cookie no se envía
- Verificar que `credentials: 'include'` esté en todas las peticiones
- Verificar CORS con `credentials: true` en backend
- En desarrollo local, usar mismo puerto o configurar proxy

### 401 Unauthorized
- Verificar que la cookie se está enviando (DevTools → Network → Cookies)
- Verificar JWT_SECRET coincide entre login y validación
- Verificar que cookie no expiró

### Cookie no se guarda en navegador
- Verificar dominio de la cookie coincide con el frontend
- En desarrollo, `secure: false` (no HTTPS)
- Verificar que no hay errores de CORS
